# Phase 5 — ML-Based Freelancer–Project Matching

This directory contains the reproducible machine-learning pipeline for the
CraftLine AI Phase 5 matching system. It predicts one of three classes:

- **Strong Match**
- **Moderate Match**
- **Low Match**

> **Synthetic-data disclaimer:** The dataset is synthetic and its labels are
> generated by a transparent rubric. The reported metrics do not establish
> real-world matching accuracy.

## Quick start

Run from the project root with the project virtual environment:

```bash
python -m ML.scripts.generate_dataset --count 1500 --seed 42
python -m ML.scripts.train_model
python -m pytest Backend/tests/test_ml.py -v
```

The training script writes the Joblib model, metadata, metrics and evaluation
report. The backend loads the model once at startup and reuses it.

## Model

| Item | Value |
|---|---|
| Algorithm | `RandomForestClassifier` |
| Version | `phase5-rf-v1` |
| Trees | 300 |
| Max depth | 12 |
| Min samples per leaf | 3 |
| Class weighting | `balanced_subsample` |
| Random seed | 42 |
| Model file | `ML/models/match_model.joblib` |
| Metadata | `ML/models/model_metadata.json` |

Actual test metrics are in `ML/reports/evaluation_report.md`. They were produced
by the training script, not copied from an external source.

## Features

The model uses eight numeric features:

1. `skills_match_percentage`
2. `required_technology_match`
3. `category_relevance`
4. `years_experience`
5. `experience_level_compatibility`
6. `avg_rating`
7. `portfolio_evidence`
8. `work_history_evidence`

See `ML/reports/feature_documentation.md` for definitions, ranges, missing-data
handling and leakage controls.

## Backend endpoints

### `POST /ml/predict-match`

Authenticated users. Request:

```json
{
  "freelancer_id": "66f1a2b3c4d5e6f7a8b9c0d4",
  "project_id": "66f1a2b3c4d5e6f7a8b9c0d2"
}
```

Response shape (values are illustrative):

```json
{
  "freelancer_id": "66f1a2b3c4d5e6f7a8b9c0d4",
  "project_id": "66f1a2b3c4d5e6f7a8b9c0d2",
  "label": "Strong Match",
  "rubric_score": 95.6,
  "match_percentage": 91.42,
  "confidence": 0.9142,
  "probabilities": {
    "strong": 0.9142,
    "moderate": 0.0715,
    "low": 0.0143
  },
  "expected_match_score": 94.21,
  "model_version": "phase5-rf-v1",
  "features": {
    "skills_match_percentage": 100.0,
    "required_technology_match": 100.0,
    "category_relevance": 1.0,
    "years_experience": 6,
    "experience_level_compatibility": 1.0,
    "avg_rating": 4.8,
    "portfolio_evidence": 1.0,
    "work_history_evidence": 1.0,
    "matched_skills": ["FastAPI", "MongoDB", "Python"],
    "missing_skills": [],
    "required_technologies": ["FastAPI", "MongoDB", "Python"],
    "matched_technologies": ["FastAPI", "MongoDB", "Python"],
    "missing_technologies": [],
    "required_technology_count": 3,
    "matched_technology_count": 3,
    "project_category": "Backend & APIs",
    "experience_level": "Expert",
    "freelancer_experience_level": "Expert",
    "project_experience_level": "Intermediate"
  }
}
```

`label` is the Random Forest's predicted class. `rubric_score` is the
deterministic 0-100 fit score from the transparent rubric applied to the live
extracted features; it is not the model probability and may differ from the
predicted label. `confidence` is the predicted-class probability.

`match_percentage` is retained only as a deprecated compatibility alias for
`confidence * 100`. It is **not** a match-quality percentage. The frontend uses
`rubric_score` for fit and shows `confidence` separately. `expected_match_score`
is a probability-weighted internal ranking score using 100/70/30 anchors; it is
not a calibrated real-world probability.

### `GET /ml/projects/{project_id}/matches?limit=10`

Client-only and owner-only. Returns public freelancer profiles ranked by
`expected_match_score`. Each item also includes the predicted `label`,
`rubric_score`, `confidence` and class probabilities. The response excludes
email, password hashes and `user_id`. The service scores up to 500 candidate
profiles.

## Security and leakage controls

- The browser sends only ids; extra feature/score fields are rejected with 422.
- Application status, hiring outcome and future information are never model
  inputs.
- The imputer and classifier are fitted inside a pipeline on training data only.
- Ranking requires the client role and project ownership.
- Public responses never expose private authentication fields.
- A missing model returns `503`; the rest of the API remains available.

## `/v1/models`

No `/v1/models` route or call exists in this repository. That path belongs to
the Gemini/Google API family and is unrelated to the matching model. The
frontend's intended ML integration is the existing `POST /ml/predict-match`
contract.

## Limitations

- Synthetic data and rubric-generated labels are not a substitute for real
  labelled hiring data.
- Reported metrics are not evidence of real-world accuracy or fairness.
- `rubric_score` is deterministic from the live features and can disagree with
  the Random Forest's predicted label. Neither value is a calibrated hiring
  probability.
- Free-text understanding is keyword/structured-field based, not semantic.
- The model should support, not replace, human hiring decisions.
